# Security

## Threat model

Pin Bridge holds Pin login tokens for many people's accounts and is the only server Pin lets in.
The main risks:

- an outsider or a malicious agency acting on another agency's accounts or listings;
- stolen tokens or keys;
- Pin Bridge being used to reach internal networks (SSRF through photo or webhook URLs);
- one agency exhausting resources shared with everyone, above all the single Pin budget.

## Controls

| Area                | Control                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Agency auth         | API key (peppered HMAC stored, never the key) plus an HMAC-SHA256 signature over timestamp, nonce, method, raw path with query, and body hash. ±5 min window. Nonces are single-use (claimed only after the signature verifies). A body that Nest did not capture raw is refused. Revocation and suspension take effect immediately.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Abuse limits        | Per-IP budget before authentication; per-key budget charged only for authentic requests; optional per-agency IP allowlist.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Enrollment          | `POST /v1/enroll` is the only unsigned endpoint. It needs an operator-issued invite code (160 bits, peppered HMAC stored, single use, 7-day default expiry, revocable), has its own per-IP limit (`ENROLL_IP_RATE_LIMIT_PER_MIN`), answers one generic 401 for any bad code, and serializes redemptions with a row lock. A retry is accepted only with the same `client_request_id` within an hour, and revokes what the first attempt issued.                                                                                                                                                                                                                                                                                                                                                                       |
| Platform enrollment | `POST /v1/platform/agencies` is signed with `PLATFORM_SIGNING_SECRET` (shared by every CRM deployment, disabled when unset) and shares the enrollment per-IP limit. Because the secret is shared, the caller must also serve `sha256(client_request_id)` at `/.well-known/pin-bridge-enroll` on the agency's own origin (`PLATFORM_AGENCY_ORIGIN`, fetched through the SSRF-safe dispatcher, no redirects). The slug is exact and the webhook must sit on that origin. Proving the domain again re-keys an existing platform agency (all earlier keys and the webhook secret are revoked, audited as `enrollment.rekey`): control of `<slug>.duckcrm.one` is what identifies the agency, so recovery needs no operator. Suspended agencies get 403; operator- and invite-made agencies are never reachable this way. |
| Pin credentials     | The Pin device key and token are stored encrypted per connection. The agency receives them once, in the confirm that activates the number. They are never returned by any other endpoint or logged.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Tenant isolation    | Every query is scoped by the authenticated agency. Foreign ids return 404. Pin `external_id` is `<slug>.<id>` (slugs have no dots, so ids cannot collide), and an item already owned by another listing is never adopted.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Secrets at rest     | AES-256-GCM, key ids for rotation, AAD bound to the row and column (a copied ciphertext does not decrypt). Pin tokens and device keys never leave the server.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| SMS                 | TT numbers only; Pin's cooldown; 5 SMS per number per 10 min; per-agency hourly budget; 5 wrong codes per SMS; 10 wrong codes per number per 24 h across all agencies.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Outbound HTTP       | https only. Every resolved address must be public, checked in the socket's own DNS lookup (no DNS rebinding). Literal IPs are checked too, including IPv4-mapped, IPv4-compatible, 6to4 and NAT64 forms. Redirects are re-checked; webhooks follow none. Size and time are capped. Only photo formats reach the image decoder, with a 50 MP pixel limit.                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Fairness            | Each agency gets at most `AGENCY_SYNC_CONCURRENCY` sync workers and `AGENCY_PIN_RPS` synchronous Pin calls. The global Pin budget sits behind a circuit breaker.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Logs                | Authorization, signatures, tokens and codes are redacted; phone numbers are masked; 5xx details never reach clients.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Deployment          | Only Caddy (443) is public; `/metrics` and `/health/ready` are blocked there. PostgreSQL and Redis sit on an internal network without internet. Containers are non-root, read-only, with all capabilities dropped. `TRUST_PROXY` trusts exactly one hop. Production refuses to start without `METRICS_TOKEN` or with the SSRF bypass flag.                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

## Review (phase 8)

An independent review of the whole codebase found no critical or high issues. These findings
were fixed, each with a test:

1. `/metrics` reachable publicly: blocked in Caddy, and `METRICS_TOKEN` is required in production.
2. One agency could use up the shared Pin budget and the publishing queue: added per-agency Pin
   budget and per-agency sync slots.
3. SMS-code guessing was unbounded across resends and agencies: added a per-number 24 h cap.
4. A lost `toggle_active` response could lead to a second toggle (wrong visibility): the real
   state is re-read before toggling, and status sync re-queues listings whose visibility drifted.
5. Pin `external_id` could collide between agency slugs: the separator is now `.`, plus an
   ownership check.
6. The per-key budget was charged before signature verification: it is now charged after, with
   a per-IP limit in front.
7. A `text/plain` body was not covered by the signature: such requests are refused.
8. `trustProxy` trusted every hop: it is now a hop count or a CIDR list.
9. IPv4-compatible, 6to4 and NAT64 IPv6 forms passed the address filter: they are now blocked,
   and SVG, TIFF and other non-photo formats are refused before decoding.

## Known limits

- Fairness is per-agency concurrency, not weighted scheduling. A very large batch from one
  agency still delays others somewhat.
- Dependencies: `npm audit` flags issues only in build-time tooling (the Prisma CLI's `mysql2`
  and `deepmerge-ts`, autocannon's `uuid`). These packages are removed from the runtime image.
- Pin's own rate limits and behaviour on production are not documented; see the questions in
  `docs/PLAN.md`.
